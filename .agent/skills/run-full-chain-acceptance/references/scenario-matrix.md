# 场景矩阵

## 通用场景车道

每个项目都要评估以下车道；不适用时写明理由，不能静默遗漏：

1. Happy path：主目标从开始到完成。
2. Alternative path：每个合法分支和取消路径。
3. Validation：空值、无效值、错误组合与错误反馈。
4. Boundary：零、负数、极值、临界日期、长文本、精度与舍入。
5. Interruption/recovery：关闭、刷新、返回、断网、服务重启和草稿恢复。
6. Concurrency/idempotency：双击、重复请求、并发修改、重试与乱序。
7. Persistence/data integrity：写入、读取、重载、迁移、隔离、删除与导出。
8. Accessibility：键盘、焦点、语义、错误关联、缩放、低视力和 reduced motion。
9. Privacy/security：最小数据、权限、敏感信息、注入、日志和真实能力声明。
10. Compatibility/responsive：支持的浏览器、设备、viewport 和降级行为。
11. Regression/operations：旧功能、构建、健康检查、日志、监控、清理和回滚。

## 用例最小字段

- Case ID、Requirement ID、风险等级、用户角色。
- 受测指纹、镜像、时间、浏览器/viewport。
- 前置状态与 seed。
- 执行前写出的预期 UI、数据、计算和日志结果。
- 操作与实际结果。
- 控制台、网络、服务和存储结果。
- 证据路径及 SHA-256。
- reviewer 身份与独立性。
- Pass/Fail/Blocked、缺陷、严重度、根因节点。
- 修复指纹、原缺陷复测、邻接回归和核心 smoke。

## 多角色视角

按产品选择角色，至少覆盖：

- 首次用户：能否理解价值、入口和下一步。
- 高频/忙碌用户：少步骤、单手、重复操作、效率。
- 谨慎用户：金额、权限、确认、撤销和解释。
- 错误/中断用户：误输入、取消、恢复和重试。
- 隐私敏感用户：数据来源、存储、导出、删除和能力声明。
- 无障碍用户：键盘、读屏语义、低视力、缩放和减少动效。
- 支持/运营：异常是否可定位，状态是否可解释。
- 工程/数据：接口、持久化、计算和幂等一致性。
- 安全/合规：信任边界、敏感信息、越权和误导承诺。
- 发布/运维：构建、启动、健康、日志、清理和回滚。

角色扮演不能替代技术独立性。对抗审查者和交叉审查者必须是不同 agent，并使用不同推导路径。

## 反形式化检查

- 每条主链至少注入一个故障或边界。
- 改 seed、重复点击或注入非法状态，确认测试确实能失败。
- 对抗审查即使没找到问题，也要列出破坏假设、反证和未覆盖风险。
- 交叉审查必须新增邻接反例，或明确证明为什么不存在。
- 任何 `Blocked`、未测或人工假定项都不能写成 `Pass`。
