# Workflow Quality Gates

This file records the generic defects the workflow must prevent and the smallest gate that prevents each one.

| Failure pattern | Design response | Release evidence |
|---|---|---|
| Every task runs the full pipeline | Route to `fast`, `standard`, or `release`; fast uses a real projection receipt, governance/documentation/maintenance may use the task-type-aware lightweight standard projection, and neither path weakens release controls | Mode/task-type route receipt and bounded check list |
| A polluted template checkout leaks private config, policy, task, runtime, evidence or adapter state into a new project | Seed install/migration defaults only from the managed, content-addressed `.agent/assets/fresh-state/v1` tree; keep source-private state outside the input boundary; leave the new project unready until atomic `project-init` binds completed guardrails, readiness and fresh context | Idle/polluted install, update/adopt/migration isolation and transaction rollback fixtures |
| Multiple roles repeatedly run the same full suite or node completion silently reruns it | Bind receipts to candidate fingerprint, runner, command plan, environment and gate tool; run affected checks in fast/standard and one full chain in release; keep reviewer-authored targeted execution fail-closed until each Case has an envelope/runner/Agent binding; make node completion verify rather than execute | One-run cap, stale-fingerprint rejection, empty reviewer `targeted_cases`, receipt-reuse fixture and no-execute completion path |
| Docker, port, credential or sandbox authority fails after most Cases already passed | Run a read-only capability preflight under the exact envelope-bound execution authority before spawn/Case 1; classify the failure as infrastructure, preserve the candidate, and require a fresh preflight without automatically reusing prior Cases after candidate changes | Missing/stale/profile-mismatched preflight and infrastructure-no-code-retry fixtures |
| Work begins before intent is aligned | Start every task in `clarification`; block all later phases until explicit approval | Approved requirement contract with source |
| Local, test, and production are mixed | Use distinct branch/environment profiles; promote one immutable artifact | Environment matrix and artifact identity |
| Validation leaves servers or containers running | Capture a project-process baseline; prefer bounded `managed-run`; otherwise register exact PID, Docker project, and port; concurrent reviewers use a lease-before-exec `tool-run` barrier; teardown on every exit path | Nested live-review validation plus `cleanup` and baseline-delta/tool-lease `assert-clean` |
| A hand-built, stale, byte-unbound, provenance-drifted or root-overridden Agent obtains review authority | Require `seal inputs → payload v2 → prepare → spawn → register → barrier`; reject missing/symlink/directory inputs and dispatch smuggling; derive the canonical verdict from the immutable report; require the exact final platform message to commit verdict/counts/report SHA; bind it all in terminal marker v6, including the exact first supervision-debt timestamp; node 7 accepts only marker-bound zero-severity PASS from exact review roles | Input drift, unprepared registration, role/deadline/old-envelope attacks, report says FAIL while root passes PASS, wrong final message, supervision-debt drift, conclusion/verdict/result/report rewrites |
| Long tasks lose decisions, repeat context or resume under changed workflow rules | Bind every transition to the previous task checkpoint and bind each checkpoint to the `policy-bundle/v2` of config, index, template manifest, workflows, the primary Skill with its `scripts/**` and `references/**`, `.agent/scripts/**.py` and `policies/PROJECT_GUARDRAILS.md` (also bound by `project_initialization.guardrails_sha256`, verified by `bootstrap-check`); replace phase summaries, unload old references and fail closed on drift/repair | Capsule, policy-bundle, task-checkpoint and handoff hashes |
| A time-expired but otherwise exact capsule forces a human repair loop | Allow ordinary sync to ignore only checkpoint age while still validating every TASK, contract, integrity, size and budget binding; all other drift remains fail-closed | Expired-valid renewal plus corrupted-expired rejection fixtures |
| TASK and active evidence grow on every retry until prompts drift | Keep four rollback entries and eight failure signatures hot; preserve cumulative recurrence counts in fully validated hash-linked archives. Archive only old unreachable evidence after deep verification, maintain a bounded index and support collision-safe exact restore | Hot/cold count, chain tamper, reachability, dry-run, restore and collision fixtures |
| A compaction boundary, failed reviewer, empty child set or host-turn boundary is mistaken for task completion | After every child terminal event, every compaction and immediately before every final reply, invoke `workflowctl route-resume`. Treat `terminal=false` as an absolute prohibition on presenting the root task as complete. Without a signed scheduler adapter, convert continuation to `waiting_host_resume` with a cursor-bound command. Only explicit `complete-task` after the terminal node and human gates may set `status=accepted,current_node=idle` | `agent-workflow-route/v2` fixtures for compact resume, child/reviewer return, missing-scheduler recovery, waiting-human pause and explicit terminal completion |
| An Agent lowers the active-window estimate by merely claiming host compaction | Require the state sequence `handoff_written → awaiting_host_compaction → resumed` and verify a `host-compaction-receipt/v1` bound to the TASK invariant and exact from/to estimates through the configured host adapter; with no adapter, lowering is unsupported | Missing-adapter, missing-handoff, stale/wrong-binding receipt and adapter-rejection fixtures |
| Fixed procedures do not fit the project | Resolve templates from the approved contract/mode/capabilities; bind outputs to manifest/source/contract; reject protected output paths | Deterministic route and stale-source attacks |
| A schema-valid Node 6 or Node 7 artifact advances without its selected dynamic template provenance | Before node advance, require exactly one mode-appropriate render record whose canonical output path, output digest/size, source digest/size, manifest digest, route digest and requirement-contract digest all match current bytes; reject missing or stale provenance before mutating accepted state | Missing-render and stale-manifest Node 6 attacks plus post-acceptance structure validation |
| Token use grows without bounds or an estimate is presented as host-measured truth | Use one total account for root usage, reference reservations and reserved/settled child charges, including sealed input, inherited fork cost, system/tool margin and output margin. Require each checkpoint to bind its own active-window estimate. Accept measured usage only from a content-addressed cumulative `agent-usage-receipt/v2` verified by the host adapter; otherwise disclose best-effort assurance, configured error ratio and possible unmetered reads. Enforce `soft`, `must_compact`, `hard_blocked` before expansion | Unified root/reference/child fixtures, receipt authority/freshness/coverage attacks, budget states and payload-bound negatives |
| Repeated test invocations each claim the full mode timeout or relabel code failures as infrastructure | Before launch, reserve remaining seconds and the sole automatic code attempt in a cross-process-locked candidate ledger; settle monotonic elapsed time and publish a content-addressed receipt. Charge dead reservations fully. Derive infrastructure only from runner-observed inability to launch or clean up, then fail closed | Oversized timeout, cumulative multi-call, second-run, dead-reservation and caller-classification fixtures |
| Child model/context silently changes, parent history is duplicated, or capacity errors loop forever | Bind every new child to the exact user/host-selected `agent_control.default_model`, `fork_turns=0`, a capsule-derived reusable payload under the mode-specific dispatch ceiling, and a fresh identity-bearing envelope in spawn/snapshot/ledger; retain historical fork metadata only for audit, content-address pre-registration capacity errors, retry that exact selected model once and never downgrade | Non-zero new fork rejection, per-mode payload ceiling, budget checks, semantic snapshot replay, stale-envelope rejection and reused-filename capacity attack |
| A barrier-waiting child is falsely killed, supervisor polling debt is confused with child death, or a truly stalled child is never stopped | Start liveness at the fresh successful-registration observation while retaining dispatch start for deadline/audit; poll at a 30-second target with 30 seconds scheduler grace; record longer gaps as supervisor debt, request status after an unchanged interval, and never interrupt because of polling debt or repeated requests alone; interrupt only at deadline or after an observed unchanged 300-second real-progress stall; a newer cursor/terminal result after a sparse interval proves current progress and cannot be reclassified as an unobserved stall; append and replay every distinct observation. Node 7 must disclose the exact selected-member debt set and request a human control waiver | Barrier-delay pass, 59-second first-poll pass, 61-second gap recorded without auto-end, exact debt/waiver mismatch, sparse-progress/terminal recovery, observed 300-second stall interruption, late-terminal, deadline-edit and historical-tamper attacks |
| Caller-authored observation JSON is overclaimed as independent platform proof | Content-address every observation for integrity and replay, but declare it an orchestrator coordination assertion. Release platform observation fails closed without `agent_control.platform_observer.signed_adapter` — human comparison alone never substitutes there; fast/standard accept caller-authored snapshots and make the Node 7 human comparison against the real tool transcript mandatory. The configured policy keeps `automatic_release_trust` false and `human_verification_required` true even when an adapter is present | Forged/manual observation cannot yield automatic acceptance; release without adapter fails closed; assurance-policy and human-waiver fixtures |
| A project Agent forges a human approval with an executable outside the repository | Default every policy-v1 human gate to fail closed. Accept an adapter only when its canonical executable and full parent chain are non-symlink, non-temporary, owned outside the current Agent identity and non-writable by that identity; an equally protected metadata sidecar must bind the executable SHA-256, dedicated purpose and exact allowed protocol operations before the adapter verifies the provider receipt. A generic interpreter, project-relative helper or Agent-created external helper has no authority | Temporary adapter plus locally authored requirement/solution/completion receipts are rejected without state mutation; protected-path validation |
| An implementation author accepts their own work | Release `agent-node-implementation/v3` names the stable initial implementer dispatch. It resolves either that completed identity or its single same-model/same-payload ledger redispatch; only the resolved orchestrator-observed implementer may commit the marker-bound, exactly eight-field `agent-implementation-attestation/v1` result for the sealed current node-6 artifact SHA, changes, checks and candidate subject. The ledger validates this result before completion. Node 7 reports the resolved identity separately from adversarial, cross and integrator roles | Alias-schema result, forged implementer string, parallel/unbounded replacement, changed payload, changed node-6 candidate, terminal-marker drift and role-overlap attacks |
| Root-authored role-play labels impersonate the cross reviewer | The cross reviewer writes one canonical six-role `SCENARIO_RECEIPT` as the third line of its sole envelope-allowlisted report; `finish` parses it before committing cross PASS or admitting integrator, the terminal report SHA commits those exact IDs, lenses, requirements, assertions, immutable evidence and outcomes, and `agent-node-acceptance/v3` accepts only a byte-equivalent scenario matrix | Missing/malformed/reordered finish-time receipt, early integrator, root-forged scenario, duplicate field/evidence and content-addressed evidence drift attacks |
| A declared adapter is mistaken for an implemented gate | Fail at node 4 unless the adapter registry names an executable runner and receipt schema | Adapter dispatch attack and live receipt |
| An implemented adapter is mistaken for verified provider, platform or hardware availability | Treat implementation as protocol availability only. Require current execution preflight for Docker/Xcode/simulator/browser/tool access and distinct signed adapters for platform snapshots, provider controls, usage, scheduler and host compaction; absent adapters/capabilities remain unverified and fail closed when required | Missing tool/runtime/hardware and null-adapter preflight negatives |
| A configured fingerprint path disappears, a manifest loses its owned source, or custom source falls outside the candidate | Let `testrun.py` own one fingerprint over all configured paths plus strict manifest/common-layout discovery beneath product roots; reject missing paths, unsafe symlinks, empty scopes, manifest-without-owned-source and drift; reuse the same digest in acceptance gates | Xcode/SwiftPM, Android, Web, API, CLI, common-layout, custom-path, symlink and candidate-drift fixtures |
| Repository prose or TASK claims remote production controls that the provider does not enforce | Bind the exact provider/repository/default branch/environments/checks/reviewer minimum into the approved requirement contract. After test, a distinct OS-protected read-only provider adapter must verify a ≤300-second receipt proving candidate reachability and successful required check runs for the exact artifact source revision, plus effective protection and environment reviewers. Approval signs the complete content-addressed decision packet; receipt/candidate/test/target drift blocks promotion. Local/test paths skip this production-only gate | Missing/caller-forged/stale/drifted receipt, wrong-revision check, exact decision-packet binding and lightweight test-path fixtures |
| A workflow upgrade turns old production history into a new deployment | Migration 26 archives v2 approved/terminal state losslessly. Only pending approved candidates may return to fresh provider preflight. Old promoted/failed/rolled-back states become `legacy_*`, carry `assurance=legacy`, expose no active release receipt, reject `promote`, and cannot mint Node8 | v25 idle/active migrations plus promoted/rolled-back no-promote/no-side-effect negatives |
| A failed deployment skips recovery | Run verification/rollback and receipt publication on failure paths, then keep the release job failed | Failure-path CI fixture and rollback evidence |

The validator enforces deterministic structure and budget rules. Product correctness still requires the mode-appropriate tests named in the requirement contract.
