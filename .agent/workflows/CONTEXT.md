# Context and Token Policy

1. Keep only `INDEX.md`, `config.json`, `state/TASK.json`, `state/CONTEXT.json` and the active Skill in working context. Every checkpoint binds a `policy_bundle_sha256` (`policy-bundle/v2`) over `config.json`, `INDEX.md`, `templates/manifest.json`, every `workflows/*.md` file, the primary Skill's `SKILL.md` plus its `scripts/**` and `references/**`, `.agent/scripts/**.py` and `policies/PROJECT_GUARDRAILS.md`; the same guardrails bytes are also bound by `project_initialization.guardrails_sha256`, verified by `bootstrap-check`. A changed policy bundle must be synchronized before work resumes; a v1 capsule is upgraded once on the next sync.
2. Validate before resuming or changing phase: `python3 .agent/scripts/contextctl.py check`. Drift in task, phase, mode, contract hash, policy bundle, decisions, questions or next action blocks work.
3. TASK-changing tools must use `contexttx.transition_task`: under one global task lock it writes side effects and TASK, creates a fresh field-level authorization containing exact old/new state and changed fields, then calls `contextctl` and rolls everything back on failure. A naked `contextctl sync --transition` with only the previous public hash is rejected. The capsule records mutator, operation, receipt hash and exact field delta; it replaces phase narration rather than appending chat history.
4. Enforce bytes, estimated capsule Tokens, list cardinality and active-checkpoint age separately from the unified `agent-total-token-budget/v1` account. The total account is root usage + loaded-reference reservations + reserved and settled child charges; every child charge includes sealed input, inherited fork cost, system/tool margin and output margin. At 60% stop loading optional references; at 75% write a verified `agent-context-resume/v1` compact handoff and continue only from its exact node; at 90% clean up, split, escalate within the mode ceiling or request a human decision. Without a verified usage adapter, assurance remains a best-effort estimate with unmetered direct reads possible. A watermark never marks the root task complete.
5. If the capsule is corrupt or its prior binding cannot be proved, run `contextctl.py repair --reset --reason <cause> --summary <reconstructed-conclusion> --source-tokens <estimate>`. Repair fails closed until `approve-repair --source user:<decision> --human-decision-receipt <provider-receipt>` verifies a provider-owned decision whose artifact SHA-256 is the exact `needs_review` capsule bytes. A caller-authored `user:` label is never sufficient.
6. References require purpose, phase, canonical path, SHA, bytes and estimated Tokens in task state. Search before reading and unload them at the phase boundary.
7. Prefer deterministic scripts and templates over repeated prose. Preserve only conclusions, evidence paths and unresolved P0/P1 items from sub-agents.
8. The capsule binds the complete canonical TASK through one SHA-256 instead of copying TASK into the capsule. This detects routing/gate/evidence drift without making context size grow with task history.
9. For each child Agent, render an `agent-task-payload-draft/v1` from the current capsule and seal project-relative regular input files into `agent-task-payload/v2`; directories use deterministic manifest files. Static migration/replay limits are 24 inputs, 131072 bytes per input, 262144 bytes total and 65536 estimated Tokens; new dispatches use tighter mode ceilings of 16000 in `standard` and 32000 in `release`, while `fast` dispatches no child. Split or escalate an oversized child task; never truncate required context. A child verifies every receipt but loads only the files and ranges needed for its current check. Render a fresh `agent-handoff-envelope/v3`, prepare with ledger `fork_turns=0`, spawn through the host with `fork_turns="none"`, register, then release `LEDGER_REGISTERED`. The capsule-derived payload is complete, so attaching parent-chat turns is forbidden duplication. Any runtime or integrator envelope also binds an execution profile and fresh capability-preflight receipt before that barrier. A retry reuses only the sealed payload and gets a new identity/output envelope. Formal review envelopes bind one chain, the exact current sealed subject, the canonical predecessor report and one report path; cross cannot prepare before adversarial PASS, and integrator cannot prepare before cross PASS. Monitoring begins at successful registration. The first elapsed unchanged interval requests status; missed polling targets are immutable supervisor debt, not authority to auto-end a child. Only a deadline or an observed unchanged real-progress gap beyond the bounded stall timeout interrupts; a newly observed cursor or terminal result after sparse polling proves current progress. A completed review report begins with its canonical verdict/count line followed by a canonical machine attestation. Cross owns six exact acceptance lenses and reuses candidate-bound full-chain evidence; integrator owns one successful clean-test receipt whose Case times fall within this integrator's marker-backed registration-to-terminal interval (five-second skew only). The exact final observation message commits the verdict plus report SHA-256. Finish copies report/replay bytes to immutable evidence and terminal marker v6 binds the complete reviewer-authored chain plus exact first supervision-debt timestamp; the root cannot replace FAIL with PASS, reuse stale or different-candidate runs, or mix historical candidates. This gives long-window continuity without replaying the full transcript or full suite.
10. After compaction, after any child terminal event, and immediately before every final reply, call `workflowctl.py route-resume`. Child completion/failure, zero active children and a host turn ending do not modify the root TASK. When the `agent-workflow-route/v2` receipt says `terminal=false`, never present the root task as complete. With no configured signed scheduler adapter, a continuation returns `waiting_host_resume` plus a cursor-bound manual recovery command. Only explicit `complete-task`, after the mode terminal node, human gates, a current empty observation and cleanup, may create `status=accepted,current_node=idle`; `waiting_human` and `waiting_host_resume` are pauses, not completion.
11. A lower active-window estimate is a host fact, not an Agent estimate. First publish the compact handoff and enter `awaiting_host_compaction` with `sync --request-host-compaction` — never a plain sync — then resume only with a `host-compaction-receipt/v1` bound to the same TASK invariant and exact from/to estimates, verified by `context.host_compaction_observer.signed_adapter`. The canonical sequence is `handoff_written → awaiting_host_compaction → resumed`. With no adapter, lowering is unsupported and fails closed. Host compaction resets only the active-window estimate; it never clears the cumulative-account `must_compact`/`hard_blocked` gates.
